# VFOPT-X-001 — live application baseline

The baseline is complete, with seven follow-ups recorded in [the findings backlog](VFOPT_X_001_FINDINGS_BACKLOG.json). This does not mean the application is issue-free. [The retained baseline JSON](VFOPT_X_001_APP_BASELINE.json) contains the measured results, methodology and limits.

Real Keycloak login, the local backend and its configured remote MySQL database were used. Production core routes became visible in about 364–547 ms, and the 100-component editor first opened in 1.86 s. Its idle main-thread work used about 0.32% of one CPU core. During the mixed-component simulation, Chromium used about 2.6 CPU cores; visible canvas rasterization was a significant main-thread cost. These are measurements on one laptop with a remote database, not production capacity guarantees.

Repeated project reads changed the timestamp used as the edit token and caused false 409 save conflicts. Live Sync also repeatedly disconnected when its native WebSocket decoder rejected larger frames. Follow-up F001 addresses revisions and persistence; F002 addresses transport limits and reconnect behavior. Rendering, heap retention, backend list queries, local connection-pool settings and optional coverage requests remain separate items.

The user requested removal of unnecessary test artifacts. Generated raw reports, screenshots, profiles and temporary audit runners have been removed. Their references in the historical JSON are provenance records, not available files. The retained JSON embeds the measurements needed to review the baseline. Reusable regression suites remain in the project.
